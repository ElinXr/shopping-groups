# Безплатен тестов сайт и онлайн база

Този вариант отговаря на изискването за нулев бюджет и липса на фиксиран 30-дневен пробен срок. Не означава неограничени ресурси или гаранция, че доставчиците никога няма да променят плановете си.

## Какво ще получи собственикът след реално разгръщане

1. Публичен HTTPS адрес от Render за отваряне на приложението от телефон/компютър и споделяне с тестери. Конкретен адрес още не е издаден.
2. PostgreSQL база в собствен Neon акаунт. Нейният проект има отделен адрес в [Neon Console](https://console.neon.tech/), със страници **Tables** и **SQL Editor** за собственика. Потребителят вече е подал създаден проект; той още не е свързан или проверен от приложението.
3. Хранилището `ElinXr/shopping-groups` в GitHub за бъдещите промени. Кодът и данните са различни неща: GitHub пази кода, Neon пази потребители, групи, продукти и история.

На тестерите се споделят само адресът на приложението и поканите за група. Паролата/connection URL на базата се въвежда като тайна в Render; тя не е публичен адрес за разглеждане на данните.

## Първа настройка

1. Създай акаунт в [Neon](https://console.neon.tech/) чрез GitHub и остани на **Free**. Създай проект `shopping-groups` в подходящ европейски AWS регион (например Frankfurt, ако е наличен). Не избирай платен план.
2. В **Connect** избери **direct connection**, изключи pooling и копирай PostgreSQL URL с TLS настройките. Приложението вече приема `postgres://` / `postgresql://` URL чрез `DATABASE_URL`; не е нужно ръчно съединяване на паролата. Директната връзка е нужна за PostgreSQL session advisory lock на фоновата обработка.
3. Качи обновения код, включително новата миграция за ключовете, в GitHub. Пакетът `artifacts/ShoppingGroups-GitHub-ready.zip`, генериран с `scripts/package-github.ps1`, вече е подреден за твоето хранилище: след разархивиране качи съдържанието му в корена, като запазиш и двете начални папки `.github` и `ShoppingGroups-V1`. Не ги поставяй в още една обща папка. Това добавя `.github/workflows/verify.yml` на правилното място и обновява кода в съществуващата папка. Проверките стартират при commit.
4. След успешни проверки в Render избери **New → Blueprint**, хранилището `shopping-groups`, branch `main`, **Blueprint Path** `ShoppingGroups-V1/render.yaml`. Този файл е за **Free** web service и не създава платени ресурси. Прегледай списъка преди прилагане.
5. Въведи `DATABASE_URL` от Neon, администраторския имейл и силна администраторска парола директно в Render. Не ги качвай в GitHub и не ги изпращай в чата. `PublicUrl` се взема автоматично от Render.
6. След успешен deploy отвори издадения HTTPS адрес и провери `/health/ready`, регистрация, две независими сесии, покана с линк/QR, общ списък, едновременно пазаруване и възстановяване. Едва тогава изпрати адреса на тестерите.

Ако по-късно преместиш проекта от `ShoppingGroups-V1` в корена, премахни/промени `rootDir` в Blueprint и работната директория на GitHub Actions заедно. Няма нужда от нов акаунт или нова база при обичайна корекция на кода.

## Локално свързване чрез Neon CLI

За вече създаден проект изпълни от корена `neon init -y --org-id YOUR_ORG_ID --project-id YOUR_PROJECT_ID --branch production --services postgres`, след това `neon deploy`. При липса на инсталиран CLI използвай `npx --yes neon@latest` вместо `neon`. Завърши входа в браузъра, ако CLI го поиска. Това настройва Neon услугите; публикуването на ASP.NET приложението остава в Render.

След като CLI изтегли настройките, `npm run dev:api` зарежда `.env`, ако съществува, иначе `.env.local`, само за API процеса. Вече зададените системни променливи имат предимство. API предпочита `DATABASE_URL_UNPOOLED`, ако е наличен, пред `DATABASE_URL`, защото фоновите задачи използват session advisory lock. Изрично зададен `ConnectionStrings__Database` има предимство и пред двете. Не добавяй database URL към променливи с префикс `VITE_`.

В друг терминал `npm run dev:web` стартира клиента. `npm run build` от корена проверява и изгражда клиента; `npm run build:api` компилира действителния .NET API. Изискват се достъп до npm/NuGet и действителна връзка с PostgreSQL. `.env*` и локалният `.neon` контекст са изключени от Git, Docker контекста и архивите за споделяне; `.env.example` остава пример без истински тайни.

Опитът от тази среда на 24 октомври спря с `ENOTFOUND registry.npmjs.org` и при инсталацията, и при `npx`. Не е извършено влизане/свързване с подадения проект и не е изпълнен `neon deploy`. Кодът е подготвен за тези настройки, но не е проверен с онлайн базата.

## Обновяване на сайта

Промени в същия GitHub branch задействат проверките. `autoDeployTrigger: checksPass` позволява на Render да публикува новия commit след успешни проверки. Данните се пазят в Neon и не се презаписват с кода. Новите схеми се прилагат чрез версионирани EF миграции.

Ключовете за Identity cookies и account tokens също се пазят в PostgreSQL (`ProtectionKeys`) в този профил, вместо в временния файлов контейнер. Тестовата Compose конфигурация упражнява същия режим. Ключовете са поверителни и трябва да се пазят с достъпа/резервните копия на базата.

## Конкретни ограничения

- Render Free заспива при неактивност; следващото отваряне може да има забавяне. Месечните квоти остават в сила. Няма фиксиран пробен край, но няма обещание за непрекъсната наличност.
- Neon Free е план без фиксиран пробен срок с квоти за база, изчисление и трафик. При изчерпване на квота достъпът може да бъде ограничен. Провери точните текущи стойности в собствения панел — някои страници на доставчика все още показват по-стари лимити.
- Blueprint проверява само `/health/live`, за да не събужда базата с всяка платформена проверка. `/health/ready` остава проверката за свързаност с базата при реален smoke test.
- Фоновата обработка е на интервал 15 минути в този профил, за да не поддържа serverless базата постоянно активна. In-app известията и SignalR промените при действия на потребителите остават непосредствени. Почистването след 90 дни става при следващата активна обработка; правото на възстановяване изтича точно на 90-ия ден.
- Render Free блокира SMTP портове 25/465/587. Докато не е настроен съвместим доставчик, поканите с линк/QR и известията вътре в приложението работят, а писмата чакат в опашката. Не се твърди, че имейл е доставен.

За имейл без фиксиран пробен срок възможен допълнителен доставчик е **SMTP2GO Free**, който поддържа STARTTLS на порт 2525. Нужни са собствен акаунт, потвърден подател и SMTP credentials. Безплатният му план има месечни/дневни/часови квоти. Настрой в Render `Smtp__Host=mail.smtp2go.com`, `Smtp__Port=2525`, `Smtp__EnableSsl=true`, `Smtp__From`, `Smtp__Username`, `Smtp__Password`. Това е документирана възможност, не проверена доставка от този проект. Писмата могат да се забавят с фоновия интервал и заспиването на хоста.
